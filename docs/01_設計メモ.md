## 1. 土台（WMSと共通）
- 構成は同じ: 画面＝単一HTML（GitHub Pages、HTTPS）／GAS＝JSON受け口（自分として実行、防御はAPP_TOKEN）／データ＝スプレッドシート
- スキャン（カメラ・Bluetoothスキャナ）、現在庫の加減算＋変更のたびに履歴を必ず残す、数式インジェクション対策、合言葉16文字以上、はWMSと同じ
- スプレッドシートはWMSとは別ブック（2026-11-09決定）。商品マスタはPOS側に独立して持つ（WMSと同型に、単価（税込）と税率区分を足した形）

## 2. 作った機能（v0.1のスコープ。設計メモv0.3の1〜9すべて）
| 画面 | 内容 |
|---|---|
| レジ | 商品ボタン（マスタから生成・絞り込み）＋バーコード（カメラ／キーボード入力）でカートへ。数量の増減・行の削除。単品の値引・割引、小計の値引・割引（円／％）。未登録商品（その場の金額・税率で販売） |
| お会計 | 支払方法（現金／カード／その他）、預り金（ちょうど・1,000・5,000・10,000のワンタッチ）→お釣り、客数（入力なしは1人）、会計を確定 → レシート表示（印刷・PDF保存） |
| 取引 | 日付ごとの取引一覧 → 取引を開いてレシートの再発行、返品（行・数量を選ぶ）、取消（全体） |
| 精算 | 日別（会計ソフト向けの日別CSVは9章）: 純売上、売上（通常）、返品・取消、取引件数、客数、客単価、支払方法別、現金の売上、税率別の対価（税込）と内消費税等。CSV書き出し（取引・売上明細・商品マスタ・入出荷履歴） |
| 商品 | 一覧・絞り込み、新規登録・編集（単価・税率区分）、CSV取り込み（`JAN,商品名,単価（税込）[,税率区分[,在庫]]`） |
| 入荷（最小） | スキャンで数えて、入荷を確定（在庫加算＋履歴） |
| 棚卸（最小） | 数えた商品の差異を出して確定（在庫を実績に。履歴は「棚卸調整」） |
| ⚙設定 | GASのURL・合言葉、音・バイブ・読み上げ、スキャナモード、**インボイスの設定**、カメラ診断 |

## 3. お金の計算の決めごと（設計メモにはなく、実装時に決めたもの）
1. **単価は税込（円・整数）**。税率は10%と軽減8%の2つ。商品ごとの税率区分はマスタに持つ
2. **値引の順**: 単品の値引・割引 → 小計の値引・割引。％は**切り捨て**（値引額）。円は、元の金額まで
3. **小計の値引は、各行の金額に按分**する（税率別の金額を出すために必要）。端数は、大きい端数の行から1円ずつ足し、按分の合計が値引額とぴったり合う
4. **内消費税額は、税率ごとの税込合計から、1枚のレシートにつき税率ごとに1回だけ**端数処理する（切り捨て／切り上げ／四捨五入は設定。既定は切り捨て）。商品ごとに処理して足す方法は使わない（国税庁Q&A 問57。例: 10%対象60,000円→5,454円、8%対象40,000円→2,962円。テストで確認）
5. **取消・返品は赤黒**: 元の取引を書き換えず、**マイナスの取引を足す**（状態「取消」「返品」、返品元の取引IDを持つ）。元の取引の状態だけ「取消済」にする。取消は全体、返品は行・数量を選ぶ。一度取り消した取引は、さらに取り消せない。返品があった取引の全体取消は不可（残りは返品で戻す）
6. **返品の金額**: その行の（値引後の）金額を、数量で按分。累計で計算するので、最後の1個で元の金額にぴったり合う。返品の内税額は、返金額（税込）から、税率ごとに1回だけ端数処理してマイナスにする。全体の取消は、元の税額をそのまま反転
7. **二重送信の防止**: 画面が会計ごとに識別子（txKey）を作り、同じtxKeyの会計は、新しい取引を作らず前の結果を返す（通信が遅くて二度押された場合でも、売上と在庫が二重にならない）
8. **マイナス在庫**: 在庫が足りなくても販売できる（レジで売れないのは困るため）。マイナスになった商品は警告を出す。`CONFIG.ALLOW_NEGATIVE_STOCK=false` で拒否にもできる
9. **客数**: 会計画面で入力（任意、省くと1人）。精算の客数・客単価に使う
10. **上限**: 1会計の明細100行、1会計の合計5,000万円、単価999万円（按分の計算を安全な範囲に収めるため）
11. **商品の単価はマスタが正**: 画面から送られた金額は使わない。未登録商品だけ、画面の金額（1〜999万円）と税率を使う

## 4. インボイス（適格簡易請求書）対応
**国税庁の説明（確認した範囲）**: 小売業・飲食店業・タクシー業などは、適格請求書の代わりに**適格簡易請求書**を交付できる。記載事項は、①発行者の氏名または名称と登録番号 ②取引年月日 ③取引内容（軽減税率の対象品目にはその旨）④税率ごとに区分して合計した対価の額（税込または税抜）⑤税率ごとの消費税額等**または**適用税率（どちらか一方でよい）。交付先の氏名・名称は省略できる（[国税庁Q&A 問58](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/58.pdf)）。消費税額の端数処理は、1枚の書類につき税率ごとに1回（[問57](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/pdf/qa/57.pdf)）。交付した書類の写しは保存する必要がある。

| 項目 | 実装 |
|---|---|
| 設定 | ⚙設定の「インボイスの設定」で、事業者名・登録番号（`T`＋13桁。全角・ハイフンは直す。形が違えば保存しない）・住所・電話・レシートのメッセージ・端数処理を、GASの「設定」シートに保存。**登録番号は、事業者が自分の番号を入れる（こちらで用意するものではない）** |
| レシート | 会計確定の直後と、取引タブの再発行で表示。①事業者名・登録番号 ②取引日時と取引ID ③明細（軽減税率は「※」と凡例）④税率別の対価（税込）⑤税率別の内消費税等（適用税率も併記）。宛先は載せない。印刷・PDF保存（ブラウザの印刷） |
| 登録番号が未設定 | レシートに「（登録番号が未設定です）」と出し、「適格簡易請求書」とは書かない。会計画面にも注意を出す |
| 取引の写し | 取引シートに、**発行時点の事業者名と登録番号**を残す（あとで設定を変えても、再発行は当時のまま）。取引・売上明細のシートが、交付した書類の控えにあたる |
| 返還（返品・取消） | 返品・取消のレシートは「返品・取消のお知らせ（適格返還請求書）」として、返還額（税込）と税率ごとの内消費税等、元の取引の日時を載せる |
| 精算 | 税率別の対価（税込）と内消費税等を日別に集計（取引ごとに1回端数処理した税額の合計） |

**この実装が保証しないこと（税理士などに確認してください）**: 登録の要否や時期、返還インボイスの記載事項・交付の免除の細かい要件（税込1万円未満の返還は交付義務が免除される旨が国税庁Q&Aにあるが、判定の単位は未確認）、交付した書類の写しの保存期間、電子帳簿保存法の要件（真実性・可視性など）、レシートを電子的に提供する場合の扱い、決済サービスを使った取引の取消。

## 5. シート構成（POS専用ブック。5枚。古い分の移し先は8章）
- **商品マスタ**: JAN／商品名／単価（税込）／税率区分／現在庫
- **入出荷履歴**: 日時／JAN／商品名／区分（販売・返品・入荷・棚卸調整）／数量（増減）／処理後の在庫数／メモ（取引ID）
- **売上明細**: 取引ID／行／日時／JAN／商品名／数量／単価（税込）／税率区分／値引／金額（税込）。返品・取消の行は、元の取引の行番号を使い、数量・金額がマイナス
- **取引**: 取引ID／日時／合計（税込）／内税（8%分）／内税（10%分）／支払方法／客数／状態（通常・取消済・返品・取消）／返品元の取引ID／取引キー／預り金／お釣り／発行者名／登録番号
- **設定**: 項目／値（事業者名・登録番号・住所・電話・税の端数処理・レシートのメッセージ）。**合言葉（APP_TOKEN）はシートに置かず、GASのスクリプトプロパティに置く**（WMSと同じ）
- 取引IDは `T-yyyymmdd-0001` の日ごとの連番

## 6. 限界・注意
- 取引・返品・取消・精算は、取引シートの**直近3,000件**、売上明細は**直近20,000行**を読む。それより古い取引は、返品・取消・精算に出ない（シートには残る）
- 会計確定は、売上明細→入出荷履歴→商品マスタ→取引、の順に書く。途中で止まった場合の自動の巻き戻しはしない（取引シートが、確定の印）
- オフラインでは使えない（会計のたびにGASを呼ぶ。電波が不安定だと確定に時間がかかる）
- 現金の過不足、レジ締めの現金カウント（金種）、釣銭機、レシートプリンタ、キャッシュドロア、決済サービス連携は未対応
- 会員・ポイント・クーポン、割込み販売、個別会計、スタッフ権限、免税、複数の支払方法の併用は、v0.1では入れない
- **個人情報は持たない**（客数は人数だけ）。取引・売上のシートは、WMSの宛先と違い、削除の仕組みはない
- スプレッドシートの共有は「制限付き」（自分だけ）にする。URLと合言葉は別々に管理し、公開しない
- 試作であり、実際の店舗のレジとして使う場合は、実機での十分な確認と、税務・会計の専門家への確認が必要

## 8. アーカイブ（v0.2.0。簡易WMS 12-18 の考え方をPOSに適用）
**目的**: 取引・売上明細・入出荷履歴は増え続けるため、終わった古い行を別のスプレッドシートへ移して、普段のシートを軽く保つ。読む範囲が直近（取引3,000件・売上明細20,000行）に限られているので、WMSほど急ぎではないが、シートの行数・CSV書き出し・セルの上限の対策になる。

**決めたこと**
- 取引（と売上明細）: 取引の日時から **N日**（30・60・90・120・180・365・0＝移さない。既定90）が過ぎたもの。取引は、通常・取消済・返品・取消のどれも「終わったもの」なので、状態は問わない。返品・取消の取引は、元の取引より新しいので、元の取引より先に移ることはない
- 入出荷履歴: 月ごとに分け、直近M か月（2・3・6・12・0＝移さない。当月を含む。既定2）だけ残す
- 移し先: 年ごとの別スプレッドシート `簡易POS_アーカイブ_<年>`、シートは月ごと（`取引_2026-10`・`売上明細_2026-10`・`入出荷履歴_2026-10`）。初回に自動作成（マイドライブ直下。ID＝スクリプトプロパティ `ARC_SS_<年>`。追加のOAuth権限は不要）
- 安全: 「アーカイブへ追記→書いた行数を確認→元から削除」。確認が合わなければ `archive_verify_failed` で止め、元は消さない。開けなければ `archive_unreachable`。追記は、同じ行がすでにあれば書かない（途中で止まっても、再実行で重複しない）。1回に移すのは取引5000件まで（古い順）
- 実行: 画面の「対象を確認」（何も変えない）→「今すぐ実行」。自動実行は**既定OFF**（ONなら1日1回、最初の通信）。時間トリガー `archiveDaily` も使える。ログ（直近10回）には、日時・件数・実行のしかたのみ

**移した取引の扱い（WMSと違う点）**
- 取引IDは日付入り（`T-yyyymmdd-0001`）で日ごとに1から始まるため、**連番の保存や索引は要らない**
- **見る**: 取引IDから開ける（レシート・インボイスの再発行も可。発行者名・登録番号は取引ごとに保存してあるので、移したあとも同じ内容）。取引タブ・精算で、移した日付を選んでも、通常のシートの分と合算して出る（二重には数えない）。「アーカイブ」タブでは、月を選んで取引・入出荷履歴の一覧を見られる
- **できない**: 移した取引の返品・取消（`archived` エラー）。返品を受け付ける期間より短い日数にしないこと
- アーカイブを開く条件: 「ここまでの日付は移したかもしれない」目印（`ARC_UPTO`）より古い日付の時だけ開く。今日・最近の日付では開かないので、アーカイブが開けなくなってもレジは止まらない
- CSVの書き出しは、いまのシートの分だけ（古い分は、アーカイブのスプレッドシートから）

**未確認**: 実シートでの動作・実行時間。取引が多い店（90日で3,000件を超える）は、日数を短くするか、`CONFIG.TX_WINDOW` を増やす（日数をどれだけ長くしても、返品・取消が探すのは、取引シートの直近3,000件まで）。

## 9. 会計ソフト向けの日別の売上CSV（v0.3.0・汎用）
- **目的**: 会計ソフトや表計算に、日々の売上を渡すための元データを出す。**特定の会計ソフトの形式（仕訳CSV）ではない**。科目・税区分・摘要は決めない
- **出し方**: 精算タブの「会計ソフト向け：日別の売上CSV」。期間（開始日〜終了日、最大366日。既定は今月）を選び、「日別の売上CSVを書き出す」。API は `dailyReport`（GETでも可、`from` `to`）
- **1日1行**（取引が0件の日は行を作らない）。最終行は「合計」。列: 日付／取引件数／客数／売上（通常・税込）／返品・取消（税込）／純売上（税込）／10%対象（税込）・10%内消費税等・10%対象（税抜）／軽減8%対象（税込）・軽減8%内消費税等・軽減8%対象（税抜）／現金／カード／その他／返品件数／取消件数
- **数え方は精算と同じ**: 金額は税込（円）で、返品・取消はマイナスの取引として入り、純額になる。内消費税等は、取引ごとに「税率ごとに1回」端数処理した額の合計。税抜は「対象額（税込）－内消費税等」。支払方法別も純額（返品は、その支払方法から引く）
- **アーカイブ済みの日付も合算**する（移す前と数字が変わらないことをテストで確認）。アーカイブを開けない時は、通常のシートの分だけで答え、画面に知らせる（`archiveError`）
- **限界**: 通常のシートは直近 `TX_WINDOW`（3,000件）まで。それより古い日付がアーカイブにも無い場合、期間の先頭の日が欠ける可能性があるので `truncated` で知らせる。期間の上限は366日
- **入れていないもの**: カード売上の入金・手数料、現金の過不足（レジ締め）、仕入・経費、仕訳の科目・税区分。申告に使う税額の計算や、インボイス・電子帳簿保存の取り扱いは、税理士などに確認する（**未確認**）
